## 3. 거버넌스 (보완 8개 반영)

### 3-1. 로그 작성자 규칙 (사전규칙)
- 모든 changelog·DECISIONS·WORKLOG 엔트리 접두: `[코드|게이트-구간|MMDD HH:MM]` (KST)
- 코드: MS 명선 / SB 새봄 / JH 정현 / BG 병갑 / GATE 판정 전용
- 예: `[SB|V2-2|0826 21:10] /ask sources 필드 스키마 변경 — 영향: JH`
- 시간 역순 적층 허용 — 접두가 있으므로 정렬·추출은 grep으로.

### 3-2. Master/Executor 전원 적용 + 권한 분리
- 팀원 각자 = 트랙 Master(claude.ai: 자기 트랙 설계·CC 검증·HANDOFF 저작) + Executor(CC: 구현·보고)
- **게이트 PASS/FIX 판정·M-xx 확정 채번·계약 문서(skeleton·BLUEPRINT) 개정 승인·HANDOFF 취합·PR 머지 = 총괄 Master(명선 세션) 단일 창구.** 트랙 Master는 "M-xx 후보"로 제안만, 타 트랙 지시 불가.
- Executor(CC)는 구현·자체 테스트·보고만 — 설계 판단·계약과 다른 임의 구현·판정 불가. 3층 표와 부트스트랩 3종 = WORKORDER §0.

### 3-3. 모델·effort 권장 (발행 프롬프트 첫 줄 표기)
- 설계·판정·문서 저작: Fable 5, effort 높음 / 정리·초안·대조: Sonnet 4.6, 낮음 / CC: 기본(감사·대형 리팩토링만 ultrathink)

### 3-4. 새 챗 체계
- 챗 제목: `코드 | V게이트-구간 | 작업내용` (예: `MS | V2-1 | 시드 감수·적재`)
- 워크로그 파일 미러: `docs/WORKLOG/V2-1_MS_시드감수.md`
- 챗 종료 시: 워크로그 작성 + 다음 챗 인계 프롬프트 출력(마지막 줄 "직전 챗: <제목>")
- 한 챗 = 한 세부구간. 넘치면 번호 증분(V2-2), 소급·b접미 금지.
- 게이트 판정은 항상 총괄 Master 챗 체인에서.

### 3-5. 게이트 크로스체크 + 강제 규칙
- 매 게이트 머지 전 전원이 09 크로스체크 프롬프트 수행 → "이상무/충돌" 보고
- **"영향: <트랙>" 표기는 PR 본문 필수. 표기된 트랙원의 GitHub Approve 리뷰가 붙기 전 머지 금지(서명 = Approve 리뷰, 코멘트 서명 불성립). — M-31** 확인 완결 책임 = 영향받는 쪽 서명.
(주: 브랜치 보호는 현재 계정 플랜(private 무료)에서 미발효 — M-31 ④는 플랜 전환 시 자동 발효 예정이며, 그전까지 강제 수단은 §3-2 총괄 Master 단일 머지 창구 + 머지 게이트 절차다. — M-31 R6 부기 2026-08-28)
